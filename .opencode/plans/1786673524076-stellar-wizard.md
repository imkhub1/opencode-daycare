# Plan: especificación del home de OpenDayCare

## Objetivo

Definir una especificación `Draft` para reemplazar el starter por el feed estático de una maestra, visualmente muy similar a `references/pantallas/feed.dc.html`, con navegación local a pantallas placeholder, sin autenticación ni base de datos.

## Alcance acordado

- El home representa el feed docente de Caro Giménez para Sala Soles.
- Los textos, nombres, fecha, publicaciones y contadores se copian como datos estáticos de la referencia.
- Se replica la composición, paleta cálida, tipografías Fredoka/Nunito, sidebar, tarjetas, badges e iconografía SVG de forma visualmente cercana, no pixel-perfect.
- Todos los enlaces visibles tendrán rutas locales.
- Las rutas que no forman parte del feed mostrarán una pantalla placeholder simple con marca, nombre de sección y enlace para volver al feed.
- En móvil se ocultará la sidebar y un menú superior abrirá/cerrará la navegación equivalente.
- No habrá autenticación, base de datos, llamadas de red, persistencia, formularios funcionales, mutación de likes/comentarios ni reproducción completa de las pantallas enlazadas.

## Archivos que documentará la especificación

- `app/layout.tsx`: metadata de OpenDayCare, idioma español y tipografías del diseño.
- `app/globals.css`: tokens globales de color y estilos base que sustituyen el tema del starter.
- `app/page.tsx`: feed principal estático.
- Componentes nuevos bajo `components/` para la navegación lateral/móvil, marca/avatar y tarjetas del feed, si la implementación los requiere para evitar duplicación.
- Rutas placeholder bajo `app/` para creación, niños, avisos, cuenta, detalle, foto y cierre de sesión, usando los paths concretos definidos durante la implementación.
- `specs/01-teacher-feed-home.md`: especificación resultante en inglés, con estado `Draft`.
- `specs/.spec-config.yml`: configuración estándar del flujo, solo si aún no existe.

## Secuencia de ejecución que deberá contener la spec

1. Actualizar la identidad global de la aplicación y sustituir el tema/metadata del starter.
2. Construir el layout responsive del feed con sidebar de escritorio y menú superior desplegable en móvil.
3. Añadir el encabezado, compositor visual, separador y las tres publicaciones estáticas de la referencia.
4. Conectar todos los enlaces visibles a rutas locales y crear placeholders simples para los destinos aún no implementados.
5. Validar tipos, lint de archivos de aplicación, build y las vistas de escritorio y móvil mediante navegador.

## Verificación prevista

- `npx tsc --noEmit` termina correctamente.
- `npm run lint` no informa errores en archivos de aplicación; se reconoce la excepción existente en `references/pantallas/support.js`.
- `npm run build` termina correctamente.
- En escritorio, `/` muestra la sidebar, encabezado, compositor y las tres tarjetas con el contenido de `feed.dc.html`.
- En una viewport móvil, la sidebar no está visible y el menú superior permite acceder a la navegación.
- Cada enlace visible navega a una ruta local; las rutas no implementadas muestran su placeholder y permiten volver al feed.
