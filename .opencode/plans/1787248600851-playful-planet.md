# Plan: Accessibility Checker Agent

## Objetivo

Crear el agente de proyecto `accessibility-checker`, invocable como `@accessibility-checker`, para auditar y corregir problemas de accesibilidad en el archivo que el usuario indique, siguiendo WCAG 2.2 Nivel AA.

## Implementación

1. Crear `.opencode/agents/accessibility-checker.md` usando la convención de agentes del proyecto: `mode: subagent`, el modelo existente `github-copilot/gemini-3.6-flash`, descripción clara y permisos en formato `permission:`.
2. Configurar permisos defensivos:
   - Lectura, búsqueda y navegación permitidas, bloqueando secretos y archivos `.env`.
   - Edición solicitada por confirmación, sin permitir cambios silenciosos.
   - Correcciones limitadas al archivo indicado y a componentes, imports o estilos directamente relacionados; no tocar dependencias, configuración, migraciones, especificaciones ni archivos no necesarios.
   - Bash restringido a validaciones del proyecto con confirmación; Playwright disponible con confirmación; sin delegación ni herramientas Supabase.
3. Definir en el prompt del agente el flujo de trabajo:
   - Exigir una ruta de archivo explícita; preguntar si falta o es ambigua.
   - Leer `AGENTS.md`, el archivo seleccionado y solo el contexto relacionado necesario para verificar comportamiento.
   - Evaluar únicamente criterios WCAG 2.2 AA aplicables, con atención a semántica, nombres accesibles, teclado y foco, formularios y errores, contraste, reflow, interacción táctil/arrastre, contenido dinámico y estados.
   - Registrar evidencia con ruta y líneas, distinguir `Cumple`, `Incumple`, `Riesgo` y `No verificable`, y no declarar conformidad total con análisis estático solamente.
   - Proponer y aplicar cambios mínimos y preservar comportamiento; detenerse y pedir decisión si la solución requiere ampliar el alcance o cambia requisitos.
   - Usar Playwright solo cuando exista una ruta/contexto ejecutable y después de obtener confirmación; documentar viewport, interacción, errores de consola y limitaciones.
4. Establecer una respuesta en español con archivo revisado, resumen, hallazgos por criterio/severidad/evidencia, cambios aplicados, criterios no verificables, validaciones, limitaciones y archivos modificados.
5. No modificar `opencode.json`, porque el descubrimiento desde `.opencode/agents/` ya está habilitado.

- Invocarlo indicando un archivo de aplicación y confirmar que produce un reporte WCAG en español, solicita confirmación antes de validaciones Playwright o ediciones, y mantiene los cambios dentro del alcance permitido.
